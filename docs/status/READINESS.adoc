= Cleave readiness — 2026-09-05

*Release decision: verified in-process kernel candidate, not production-beta
approved for the whole distributed membrane contract.*

== Implemented and tested

The Rust kernel provides a finite ranked ownership tree, staged teardown,
soft/hard leases, posture mapping and audit observations. Handles are bound to
their issuing Surface by shared-state identity, including after a Surface move.
Foreign mint/adopt/heartbeat operations fail before mutation; `try_teardown`
returns a foreign receipt intact. The compatibility `teardown` API panics before
mutation on foreign input; callers requiring recovery must use `try_teardown`.

Lease renewal rejects expired hard leases even before a delayed tick, and rejects
backwards time. Duration arithmetic is saturation-safe. Expiry is driven by the
caller's `tick`: the kernel does not provide an autonomous scheduler.

On Rust 1.97.1, locked tests pass in debug (18 runtime tests) and release (17),
plus the compile-fail doctest. The debug-only leak detector accounts for the
count difference. One boundary test exhausts all 720 increasing labelled trees
on seven nodes, checking unique releases and children-before-parent ordering.
This finite enumeration is a property test, not a universal theorem.

== Mathematical boundary

The five Idris modules prove statements about their inductive models. See
link:../../proofs/README.adoc[the honesty ledger] and
link:../PROOF-NEEDS.adoc[the canonical obligations]. Cardinality of a rank list
is not an identity-uniqueness proof; a size-minus-length residue measure is not
an observation of OS resources. No extraction or checked Rust refinement exists.

General DM accessibility, distributed joint completion (O-6), and clean-versus-
rupture treatment (O-7) remain open. Rust's move restriction does not prevent a
caller from deliberately forgetting a handle; release builds have no leak bomb.
The kernel's single-process tests cannot establish remote endpoint behavior.

== Verify and operate

[source,bash]
----
cargo test --locked --all-targets
cargo test --locked --doc
cargo test --locked --release
cargo clippy --locked --all-targets -- -D warnings
bash tests/check_proofs.sh /absolute/path/to/evidence
----

Consumers must drive lease ticks, consume teardown reports, and test their own
native resource cleanup. Released-node receipt metadata and the append-only
audit remain allocated for the lifetime of a Surface; use a bounded-lifetime
Surface per owning context and drop it after teardown. A global, ever-growing
Surface is not a bounded-memory service, and long-running capacity/load testing
of the actual embedding remains a beta requirement. Before beta, capture the live consumer pairing, satisfy
the CRG home-context and six diverse external-target requirements, obtain green
remote CI, and choose/rehearse the actual deployment and rollback process.
Machine-readable descriptions use `.machine_readable/descriptiles/`.
