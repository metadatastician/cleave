= Architecture Topology

== System Overview

Cleave is the *surface* of the joinery trio (cleave = surface, groove =
protocol, spline = data-form/wire): a transmutable dial whose kernel
demonstrates ranked ownership with clean-XOR-rupture teardown at exactly one
dial point (2026-07-09, per the repo's own bar in `docs/PROOF-NEEDS.adoc`).
The kernel is deliberately small and dependency-free; everything protocol- or
wire-shaped lives in groove/spline, and cleave's remaining XL obligations are
wire-blocked on spline (see `docs/architecture/THE-JOINERY.adoc`).

  `DMMultiset` (Dershowitz–Manna step lemma), `HandleLinearity`
  (`teardown : (1 h : Handle) -> Perp`). Mirrors guard running code; they are
  not extracted code (stated in the honesty ledger, `proofs/README.adoc`).

| The v0.3-draft cleave standard (RC-1..13 + TS-1..7), consumed by groove and

| `.github/workflows/kernel.yml`

== Joinery Edges

----
        spec/registry (SSOT)            wire (future)
groove ─────────────────────▶ cleave ◀──────────────── spline (src-less until
   │                                                    ADR-0005 bar is met)
   │ groove §4.6 leases
   ▼
gossamer (consumer; owns the groove ABI proofs)   burble (provider; owns .bop)
----

* Every cleave edge is *protocol or spec* — the joinery's only compile-time
  edge is panll→gossamer, which does not touch cleave. Dominant risk is
  contract drift, not build order; hence gates over sequencing.
* Cleave's Tier-A frontier (O-6 joint completion, O-7 clean-XOR-rupture over
  a wire, TS-5 multi-process re-dial, TS-7 posture-never-on-wire) needs real
  bytes between processes; that wire is spline. Working on spline *is*
  working on cleave.
* The G-2/G-3 gossamer legs are machine-verified by gossamer's
  `ABI Typecheck Gate` + `E2E + Safety` workflows (green 2026-08-03; run IDs
  in the ledger).

== Deployment

Cleave ships no service. Its artefacts are the kernel crate (unpublished), the
proof mirrors, and the standard; CI is the only runtime.
